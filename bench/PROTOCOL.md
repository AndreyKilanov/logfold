# Benchmark protocol

The protocol is fixed **before** results are produced. Commands are in `bench/run.py`; datasets in `bench/gen.py`.

## Question

How fast does logfold fold a large log into templates, and compare two runs, relative to other tools doing the same work,
on one machine, with comparable output?

## Competitors

| Tool | Version source | How it is run |
|---|---|---|
| [Drain3](https://github.com/logpai/Drain3) | PyPI, version recorded in the results | `bench/competitors/drain3_run.py`, reads the file line by line, `add_log_message` |
| [logdrain](https://github.com/vnvo/logdrain) | `cargo install logdrain-cli`, release build | `logdrain FILE --format csv --min-size 999999999 --sim-th 0.4 --depth 4` (prints nothing, mines everything) |
| [logdelta](https://github.com/antonsoo/logdelta) | `cargo install logdelta`, release build | `logdelta templates FILE --threshold 0.4`, `logdelta diff BEFORE --target AFTER --threshold 0.4 --json` |
| logfold | this repository, `maturin develop --release` | `python -m logfold analyze|diff ...` |

## Datasets

Generated by `bench/gen.py` (seeded, byte-identical for the same arguments), 100 MB each:

| Name | What it is |
|---|---|
| `nginx` | combined access log, 7 pages, ids in API paths |
| `app` | 12 message templates, six services, timestamps, ids, IPs |
| `loghub` | Loghub-2k samples (HDFS, Apache, OpenSSH, Linux, Hadoop, Zookeeper, Spark, Thunderbird) with randomised digits |
| `highcard` | adversarial: 6–15 random words per line from a 60 000-word vocabulary, ~10⁵ templates |
| `*_b` | the "after" run of a diff pair (`nginx`, `app`): new templates, a changed error rate, a removed template |

Large Loghub-2.0 files could not be downloaded when the first results were produced (Zenodo returned 403). Quality is
measured separately on Loghub-2k (`eval/quality.py`).

## Scenarios

- `analyze-bare`: no value masking in any tool. Isolates the miner.
- `analyze-masked`: each tool's masking at its recommended setting: logfold default rules (uuid, ts, ip, hex, path, num), Drain3
  with the same six regexes, logdrain `--masks uuid,hex32,ipv4`, logdelta built-in masks (cannot be disabled). The work is
  not identical across tools; the template counts in the results show how different the outputs are.
- `diff`: logfold `diff` (with and without the recount pass) and `logdelta diff`.

Parameters aligned across tools: depth 4, similarity threshold 0.4, plain text, whole file.

## Measurement

- Each command runs as a separate process, standard output discarded.
- Recorded: wall time, CPU time (user + system), peak working set (`psutil`, Windows `peak_wset`).
- Repeats: 3; the median is reported with min and max. A run that fails or exceeds the timeout (900 s) ends the repeats
  for that tool and is reported as such.
- Files are read from a warm page cache (100 MB files, repeated runs). Cold-cache behaviour is not measured.
- Interpreter start-up and imports are included for Python-based tools (that is what a user waits for).

## Equivalence of work

Speed is only comparable if the output is. `eval/quality.py` checks grouping accuracy on Loghub-2k: logfold's sequential
strategy reproduces Drain3's templates (same grouping accuracy and template counts on all 16 datasets). Template counts on
the benchmark datasets are recorded next to the timings.

## Decision rules (from the specification)

- Against Drain3: the hypothesis was 20–50×; below 5× the positioning must be reconsidered.
- Against logdrain: not worse in one thread, better in parallel mode.
- A comparison where logfold loses must be published as it is.

## Reproduce

```
python bench/gen.py --out bench/data --size-mb 100
python bench/gen.py --out bench/data --size-mb 100 --variant b --only nginx app
python bench/run.py --repeat 3
python bench/report.py
```
